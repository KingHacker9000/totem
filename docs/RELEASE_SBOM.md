# Release SBOM

Totem's public application/deployment release emits a deterministic **CycloneDX 1.6 JSON** software bill of materials (SBOM) for the shipped/runtime JavaScript dependency boundary.

The SBOM is generated by `scripts/release-sbom.mjs`. It intentionally reuses the existing release authorities instead of maintaining another dependency inventory:

- `scripts/third-party-manifest.mjs` defines the runtime-versus-build/development dependency split and the public/private redistribution boundary;
- `scripts/release-bundle.mjs` defines the exact public source/deployment artifact and its source revision, Git tree, and aggregate SHA-256 digest;
- the SBOM combines those two identities and fails if they refer to different source revisions or if the private Portal exclusion boundary is missing.

## Commands

After a frozen install, generate the SBOM with:

```bash
pnpm release:sbom:generate
```

This rebuilds the deterministic public bundle and writes:

```text
dist/release/totem-public.sbom.cdx.json
```

Verify a previously generated SBOM against the current exact source, bundle, lockfile, and runtime dependency graph with:

```bash
pnpm release:sbom:verify
```

Verification regenerates the expected CycloneDX document in memory and byte-equivalent JSON comparison fails closed when the artifact identity or dependency boundary drifts.

## Determinism and artifact linkage

The document deliberately omits wall-clock timestamps and machine-local paths. Stable component ordering and property ordering make repeated generation from the same clean source and lockfile byte-identical.

The root CycloneDX application component records:

- exact Git source revision;
- exact Git source tree;
- deterministic public release-bundle SHA-256;
- `pnpm-lock.yaml` SHA-256 from the T924 third-party manifest logic;
- SHA-256 of the canonical T924 third-party manifest content used for generation;
- the explicit `public-only` release boundary.

Runtime components use exact package names and installed versions from the production dependency graph. Build/development-only packages listed by the T924 manifest are deliberately excluded. Private `totem-portal-theme` and `totem-portal-hardware` repositories/assets remain outside the public SBOM and public release contract.

## Limitations

This SBOM is an inventory and identity artifact, not a vulnerability verdict or a license decision. T913 remains the owner-controlled Totem licensing gate. Known-vulnerability policy is handled separately so advisory-database freshness does not make the deterministic SBOM itself non-reproducible.

Externally supplied executables, models, and voices recorded by the T924 manifest are not represented as shipped CycloneDX components because they are not part of the public Totem release artifact. If a future release bundles them, the release boundary and SBOM generator must be updated together.
